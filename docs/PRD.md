## 1. 文档目的

本文档描述 `card-vault-home` 公开产品官网的目标、用户、范围、内容结构、功能需求、非功能需求和验收标准，用于维护当前实现并指导后续迭代。

本文档只覆盖产品介绍网站，不覆盖卡沃 iOS App 的具体业务实现。App 源代码、内部设计和开发文档位于私有项目中，不通过本网站公开。

## 2. 项目背景

卡沃（CardVault）是一款完全离线运行的 iPhone 卡片保险箱，用于在当前设备上保存身份证件、银行卡的结构化信息及正反面照片。产品以“数据只留在本机”为核心原则，不提供账号、云端同步、广告或行为分析。

CardVault Home 是产品的公开信息入口，承担以下职责：

- 用清晰、可信的方式说明产品定位与核心价值。
- 解释本机 OCR、加密存储、安全认证和受控复制等能力。
- 明确产品不提供的功能以及由此产生的数据恢复边界。
- 公布当前发布状态与目标平台。
- 提供隐私政策和公开支持入口。
- 在不暴露私有产品代码仓库的前提下承载公开信息。

## 3. 产品目标

### 3.1 核心目标

1. 让首次访问者在首屏快速理解“完全离线的 iPhone 卡片保险箱”。
2. 通过可验证的产品原则和数据流程建立隐私信任。
3. 清楚说明 1.0 版本的能力、限制和当前发布进度。
4. 满足 App Store 发布所需的公开隐私政策与支持页面需求。
5. 保持网站轻量、稳定、无需后端即可长期维护。

### 3.2 成功标准

- 访问者无需阅读源代码即可理解产品用途、隐私原则和版本状态。
- 首页、隐私政策和帮助支持页面可通过清晰导航互相到达。
- 页面在桌面与手机浏览器中均可正常阅读和操作。
- 网站不包含追踪脚本、广告 SDK、账号系统或业务数据收集表单。
- 推送至 `main` 分支后可通过 GitHub Actions 自动部署。
- 公开页面不链接或暴露私有产品代码仓库。

## 4. 目标用户

| 用户类型 | 核心需求 |
| --- | --- |
| 潜在用户 | 快速了解卡沃能保存什么、如何保护数据、何时可以使用 |
| 隐私敏感用户 | 确认数据是否上传、是否存在追踪、能否远程恢复 |
| App Store 审核人员 | 查看产品介绍、隐私政策、支持方式和版本信息 |
| 已有用户 | 查找常见问题、数据删除方式和支持入口 |
| 项目维护者 | 更新发布状态、政策内容和公开支持信息 |

## 5. 核心用户路径

### 5.1 了解产品

访问首页 → 阅读首屏定位 → 查看核心能力 → 理解本机处理流程 → 查看发布状态。

### 5.2 验证隐私边界

访问首页 → 阅读隐私原则和明确边界 → 进入隐私政策 → 了解数据处理、权限、保留与删除规则。

### 5.3 获取支持

访问首页或隐私政策 → 进入帮助与支持 → 阅读常见问题 → 必要时通过公开 GitHub Issues 提交问题。

提交公开问题前，用户应被提醒移除姓名、证件号码、银行卡号、CVV/CVC、卡片照片、App 密码等敏感信息。

## 8. 非功能需求

### 8.1 技术与兼容性

- 网站必须使用原生 HTML 与 CSS 实现，不依赖 Node.js、前端框架或客户端构建流程。
- 核心内容在 JavaScript 不可用的情况下仍需完整显示和操作。
- 支持当前主流版本的 Safari、Chrome、Firefox 和 Edge。
- 布局需适配桌面、平板与手机视口，不产生阻断阅读的横向滚动。
- 所有内部页面和静态资源使用相对路径，保证本地文件预览与 GitHub Pages 子路径部署均可使用。

### 8.2 性能

- 首屏不加载第三方字体、视频或大型脚本。
- 图片资源应控制数量和体积；当前正式 App Icon 为主要位图资源。
- 页面不应因装饰效果阻塞主要内容显示或交互。

### 8.3 可访问性

- 使用语义化标题层级、导航、列表、文章和页脚结构。
- 交互链接和按钮需具备可识别文本，不仅依赖颜色表达含义。
- 装饰性图片使用空替代文本，承载信息的视觉区域提供可理解的辅助说明。
- 键盘用户可以访问所有链接、FAQ 和页面导航。
- 文字与背景保持足够对比度，并尊重系统减少动画偏好。

### 8.4 隐私与安全

- 网站不得加入广告、用户画像、跨站跟踪或行为分析 SDK。
- 不提供收集卡片信息、身份信息、密码或支付信息的表单。
- 页面示意数据必须为虚构或脱敏数据。
- 不公开私有产品代码仓库的地址或将其作为用户入口。
- 对外链接必须指向明确、可信且与当前公开项目相关的目标。

### 8.5 可维护性

- 首页、隐私政策和支持页面共用 `styles.css`，减少重复样式。
- 产品状态、系统版本、隐私政策生效日期等易变化信息应定期核对。
- README 提供英文与简体中文两个独立版本，并可互相切换。
- 重大内容或数据处理变化需要同步更新本 PRD、网站与隐私政策。

## 9. 视觉与内容规范

### 9.1 视觉方向

- 整体采用接近 iOS 深色界面的黑色背景、白色正文和系统蓝强调色。
- 通过蓝色、深灰及紫橙渐变卡片呼应真实 App 的卡片视觉。
- 手机示意图只表现产品内容，不展示伪造的系统时间、信号或电池状态栏。
- 固定顶部导航使用半透明背景和适度模糊，滚动时保持层级清晰。

### 9.2 文案原则

- 先说明用户收益，再解释技术实现。
- 对隐私、安全和数据恢复能力使用明确表述，避免无法验证的绝对承诺。
- 发布前不得出现无效的下载、关注进展或私有仓库跳转按钮。
- 支持入口只能指向实际可访问的公开页面。
- 版本状态变化后，首页、FAQ、支持页和 README 中的描述应保持一致。

## 10. 部署与发布要求

1. 网站源文件保存在 `card-vault-home` 公开仓库的 `main` 分支。
2. `.github/workflows/pages.yml` 在推送至 `main` 后触发部署。
3. 工作流直接上传仓库中的静态文件，不执行依赖安装或构建命令。
4. GitHub Pages 环境部署成功后，公开地址保持为 <https://marc-ing.github.io/card-vault-home/>。
5. 发布前需要检查页面链接、静态资源、响应式布局、隐私文案和公开仓库边界。

- [ ] 手机示意图不包含系统状态栏，且只使用脱敏示例。

- [ ] 页面没有私有产品代码仓库链接。

## 12. 当前版本不包含

- CardVault iOS App 源代码、技术架构或内部开发资料的公开访问。
- 用户注册、登录、订阅、支付或账号管理。
- 云端卡片存储、跨设备同步或远程数据恢复。
- 在线下载、TestFlight 邀请或 App Store 跳转；正式上架前不展示无效入口。
- 联系表单、邮件订阅、在线客服或服务端工单系统。
- 第三方统计、广告投放、个性化推荐或用户行为追踪。
- 网站多语言页面；当前公开网页以简体中文为主，项目说明文档提供英文与简体中文版本。

## 13. 后续迭代建议

以下内容仅在真实资源可用且不改变隐私边界时考虑：

1. App Store 上架后增加正式下载链接，并同步更新 FAQ 与发布状态。
2. 根据真实发布版本更新系统要求、功能状态和支持说明。
3. 如面向更多地区发布，可增加独立的英文网站页面与英文隐私政策。
4. 增加自动化链接检查与基础 HTML 可访问性检查。
5. 当 App 数据处理方式发生变化时，优先更新隐私政策并记录生效日期。
